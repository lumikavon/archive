# 小红书英语音标内容的 IPA 语音合成方案

> 适用场景：48 个英语音标学习卡、跟读儿歌、课堂节奏练习和小红书竖屏教学视频。
> 核心结论：发音与音乐分轨制作。由专业 TTS 或真人录音负责发音，Suno/Udio 只负责生成无人声背景音乐，最后再进行混音和人工复核。

## 1. 方案目标

### 1.1 质量目标

- 音标符号、示例单词和中文提示与内容底稿一致。
- 长短元音、清浊辅音和易混淆音对比清楚，语速适合儿童跟读。
- 人声与背景音乐可以独立修改，便于替换错误音频、调整节奏或重新剪辑。
- 每个发布版本都保留可追溯的文本、音频、混音和校对记录。

### 1.2 边界说明

- 不把“AI 生成”视为发音正确的证明，也不承诺未经复核的“绝对标准、零误差”。
- 音乐生成模型不作为 IPA 发音引擎使用；它可以生成氛围和伴奏，但可能跳词、改词或误读音标。
- 具体引擎是否支持 IPA/SSML、支持哪种语法以及是否允许商用，必须以项目当前版本的官方文档和授权条款为准。

## 2. 推荐制作链路

```text
内容底稿
  → 音标与词例校核
  → 拆分配音单元
  → 专业 TTS/真人录音
  → 逐词听检与修订
  → 生成无人声 BGM
  → 人声优先混音
  → 导出与播放检查
  → 小红书发布素材复核
```

| 阶段 | 主要工作 | 产物 | 通过条件 |
|---|---|---|---|
| 内容整理 | 确认音标、词例、释义和节奏尾句 | 定稿脚本 | 与音标表逐项对应 |
| 发音生成 | TTS 或真人录制音标、单词和句子 | 人声分轨 | 目标音和词例均可辨认 |
| 发音校对 | 对照标准音频/口型资料逐词试听 | 修订记录 | 错读、漏读、跳词已处理 |
| BGM 制作 | 生成或选用无歌词、无人声伴奏 | BGM 分轨 | 不遮盖辅音和词尾 |
| 混音导出 | 调整人声、BGM、停顿和淡入淡出 | 成品音频/视频 | 手机外放和耳机试听均清楚 |
| 发布复核 | 检查字幕、封面、授权和版本 | 发布包 | 文案、音频和素材相互一致 |

## 3. 内容底稿与标注规范

### 3.1 文件职责

本目录中的文件建议按以下职责使用：

1. [48个英语音标表](./音标/48个英语音标表.md)：发音事实、分类、示例单词和 IPA 的校核底稿。
2. [48个英语音标儿歌](./音标/48个英语音标儿歌.md)：TTS 或真人配音的跟读正文，包含三遍音标、三遍单词和中文节奏尾句。
3. [48个英语音标儿童歌曲-Suno版](./音标/48个英语音标儿童歌曲-Suno版.md)：音乐平台的教师领读/儿童回应格式，仅作为歌曲脚本和音乐生成参考，不作为发音准确性的依据。

### 3.2 统一文本规则

- 教学文档和字幕中的音标统一使用方括号，例如 `[iː]`、`[tʃ]`。
- 不要求 TTS 把“方括号”三个字读出来；需要朗读时只读其中的目标音。
- Suno 等平台可能把方括号解释为段落或结构提示。投喂歌曲平台时，可按平台规则改用全角圆括号 `（ ）`，但这只是输入格式变化，不代表 IPA 语义发生变化。
- 一个标准配音单元包括：目标音标连续 3 遍、3 个示例单词各 3 遍、中文节奏尾句。若为短视频而缩短内容，应在脚本中明确删减范围，不要让模型自行压缩。
- `[tr]`、`[dr]`、`[ts]`、`[dz]` 按国内传统 48 音标教学体系保留为“辅音组合”；对外说明时注明这与现代语言学的分析方式可能不同。
- `[ʊə]` 及部分示例词在不同英式口音中的实际读音可能变化，发布前应固定目标口音并采用同一套校对标准。

## 4. TTS/真人发音方案

### 4.1 引擎选择原则

专业 TTS 的职责是稳定、清晰地读出音标和示例词；真人录音可作为难读音、特殊重音或 TTS 反复失败时的替代方案。

下列服务可作为候选，不能直接视为已确认能力：

| 候选 | 需要先确认的事项 |
|---|---|
| MiniMax 语音 API | 当前模型是否接受 IPA/音素或 SSML、具体标签语法、语言/音色限制、商用授权和配额 |
| Verbatik | 当前接口是否支持 SSML/IPA、英式英语音色、输出格式、授权范围和稳定性 |
| ElevenLabs Speech | 当前模型的音素/SSML输入方式、英式音色、用量限制、商业计划和内容授权 |

选型前至少完成一次小样本验证：用 `[iː]`、`[ɪ]`、`[θ]`、`[ð]`、`[ŋ]`、`[tr]`、`[dz]` 以及 `see / sit / think / this / sing / tree / beds` 进行试听，并记录模型、音色、参数、生成时间和结果。未经验证的服务名称不应写成“支持 IPA”的确定性结论。

### 4.2 输入与生成策略

1. **先整理普通文本，再决定标注方式。** 将音标、英文词、中文提示和停顿拆成字段，避免把整首儿歌作为一条超长请求直接交给模型。
2. **只有在官方语法确认后才使用音素/SSML。** 不同服务的标签名称、属性和转义规则不同；普通文本框不一定会把 IPA 字符解释为发音标注。
3. **按可替换单元生成。** 推荐至少分成“目标音标”“示例单词”“中文尾句”三类分轨，必要时再按每个词拆分。这样可以单独替换误读音，而不必重做整段。
4. **优先选择清晰、克制的教学音色。** 语速略慢，停顿明确，避免唱腔、夸张情绪、过度混响和过强自动修音。
5. **生成后人工听检。** 对每个音标和每个示例词逐项试听；若 TTS 连续读错，改用确认过的标准发音或真人领读，不要只靠改写拼写反复碰运气。
6. **保存生成元数据。** 至少记录服务、模型/版本、音色、参数、输入脚本、生成日期和人工校对结论，便于复现和追责。

### 4.3 推荐的单元脚本格式

以 `[iː]` 为例，配音输入可先整理成以下结构；实际 IPA/SSML 标签按所选服务的官方语法映射：

```text
目标音： [iː]、[iː]、[iː]
示例词： see、see、see；green、green、green；teacher、teacher、teacher
节奏尾句：看一看，绿一片，老师笑得甜。
```

如果引擎不支持可靠的 IPA/音素标注，则保留英文示例词和真人/标准音频校对，不把未确认的 IPA 字符串强行塞入普通文本输入框。

## 5. 背景音乐方案

### 5.1 音乐生成定位

Suno/Udio 只生成不含教学人声的 BGM。原始提示词可整理为：

```text
Pure acoustic guitar, slow, educational background music, instrumental only, no lyrics, no spoken voice, sparse arrangement, leave space for narration.
```

可根据视频时长调整伴奏长度或循环方式，但不要让音乐模型承担音标、示例单词或中文讲解的朗读任务。

### 5.2 BGM 选择标准

- 无歌词、无旁白、无人声采样和明显的语音片段。
- 节奏稳定、编曲简洁，给爆破音、摩擦音和词尾留出空间。
- 避免强低频、密集打击乐、突然的音量跳变和过长的混响尾巴。
- 保存生成平台、提示词、版本和授权凭据；发布前确认当前计划允许小红书使用。

## 6. 混音与导出

1. 以人声为主轨，先把音标和示例词的清晰度调到合适，再加入 BGM。
2. BGM 可先以“比人声低约 12 dB”作为起始点，再根据实际响度、手机外放和耳机试听微调；`-12 dB` 是起点，不是所有内容都适用的硬性标准。
3. 人声出现时对 BGM 做适度自动闪避（ducking），尤其注意 `[f]`、`[s]`、`[ʃ]`、`[θ]` 等高频摩擦音不能被伴奏盖住。
4. 检查起止点、停顿、淡入淡出、左右声道、削波和明显底噪。不要用过度压缩换取响度，以免清浊对比消失。
5. 同时保留人声分轨、BGM 分轨和最终混音文件。最终视频按发布工具要求导出，并在手机外放、普通耳机和安静环境下各试听一次。

## 7. 发布前校对清单

### 文本与 IPA

- [ ] 音标、示例词、释义与音标表逐项一致。
- [ ] 目标音标和每个示例词的重复次数符合脚本要求；没有漏读、跳词、合词或擅自改词。
- [ ] 长短元音、清浊辅音、鼻音和词尾辅音已单独检查。
- [ ] `[tr]`、`[dr]`、`[ts]`、`[dz]` 的教学分类已按项目口径标注。
- [ ] `[ʊə]` 等存在口音差异的项目已注明目标口音或采用统一参考音频。

### 音频

- [ ] 逐词人工试听通过；关键音至少由第二位熟悉英语标准发音的人员抽检。
- [ ] 人声在 BGM 上方清楚可辨，词首、词尾和清浊对比没有被掩盖。
- [ ] 无削波、爆音、明显底噪、异常停顿、断句或模型跳段。
- [ ] 成品与手机外放、耳机播放场景相容。

### 发布与合规

- [ ] TTS、真人录音、BGM、图片、字体和视频模板的授权范围已记录。
- [ ] 发布文案不把未经验证的引擎能力写成保证，不宣传“零误差”等无法证明的承诺。
- [ ] 成品字幕、封面和音频使用同一版脚本；修改后重新生成校对记录。
- [ ] 版本号、生成日期和最终文件已归档，便于撤换或回滚。

## 8. 建议的文件组织

每个音标或每条视频建议独立成一个小包，示例：

```text
01-i-long/
├─ script.md       # 定稿脚本与 IPA 校对结果
├─ voice.wav       # TTS/真人人声分轨
├─ bgm.wav         # 无人声背景音乐分轨
├─ mix.wav         # 归档用最终混音
├─ publish.mp4     # 小红书发布版本
└─ qa.md           # 听检、授权和导出记录
```

当前归档中的学习卡文件名覆盖 `01`—`10`。如果目标是完整发布 48 个音标，应在同一制作链路下补齐其余视觉素材，并在发布排期中标注已完成和待补齐的编号。

## 9. 最小可执行版本

若先做一条样片，可按以下顺序落地：

1. 从音标表选取一组易混淆音，例如 `[iː]` 与 `[ɪ]`。
2. 用跟读稿生成两段独立人声；分别校对音标和示例词。
3. 用“慢速、教学、无人声”的提示词生成一段简洁 BGM，并确认授权。
4. 以人声为基准将 BGM 先降低约 12 dB，完成闪避、淡入淡出和导出。
5. 在手机外放和耳机上试听，确认字幕、音频和学习卡一致，再复制模板扩展到其他音标。

## 10. 结论

最稳妥的生产方式是“专业发音轨 + 无人声 BGM + 后期混音 + 人工校对”。TTS 负责提高批量生产效率，Suno/Udio 负责提供轻量的音乐氛围，准确性则由内容底稿、标准参考音频和发布前人工复核共同保证。
