# 虚拟资料竞品数据库字段规范 v1.0

- 版本：v1.0
- 目标：定义 AI Agent 持续采集、去重、更新、比较虚拟资料竞品时的统一字段、实体关系和校验规则。
- 设计原则：一条事实对应一个可复核来源；动态数据保存快照；逻辑产品与平台上架页面分离；未知值保持空值。

## 1. 推荐数据模型

建议最少拆成 7 个逻辑实体：

| 实体 | 主键 | 作用 |
|---|---|---|
| `competitor` | competitor_id | 创作者、品牌、店铺、机构主体 |
| `product` | product_id | 逻辑上的产品/资料包 |
| `listing` | listing_id | 某产品在某平台上的具体上架页面 |
| `evidence_snapshot` | evidence_id | 某时点可见的互动/销量/评价/页面证据 |
| `price_snapshot` | price_id | 价格和促销变化历史 |
| `review_insight` | insight_id | 用户评价/评论中提取的需求与缺口 |
| `change_event` | event_id | 新竞品、价格、形态、规则、评分等变化 |

如果早期只使用 CSV/Excel，也应保留这些 ID，方便未来迁移 SQLite/PostgreSQL。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| competitor_id | string | 是 | 内部稳定 ID，如 `cmp_xhs_000001` |
| competitor_name | string | 是 | 公开名称/店铺名/作者名 |
| entity_type | enum | 是 | `creator/brand/store/institution/unknown` |
| primary_platform | string | 是 | 小红书、Etsy、Gumroad、淘宝等 |
| platform_account_id | string | 否 | 公开可见且稳定的平台 ID；不可见则空 |
| profile_url | url | 否 | 公开主页 URL |
| region | string | 否 | 国家/地区，仅记录公开可确认信息 |
| main_lane | string | 否 | 主要赛道 |
| first_seen | date | 是 | 第一次发现日期 |
| last_seen | date | 是 | 最近一次核验日期 |
| status | enum | 是 | `active/inactive/unknown` |
| notes | text | 否 | 其他公开观察，不写敏感个人信息 |
## 3. product 表

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|

| competitor_id | string | 是 | 关联 competitor |

| main_lane | string | 是 | 主赛道 |
| sub_lane | string | 是 | 细分赛道 |
| audience | string | 否 | 目标人群 |
| job_to_be_done | text | 是 | 用户试图完成的具体任务 |
| task_stage | string | 否 | 任务阶段，如签约前/水电验收/面试前 |
| product_format | enum | 是 | PDF/Excel/Word/PPT/Notion/Prompt/图纸/组合包等 |
| deliverables | text | 是 | 实际交付物列表，不只记录营销标题 |
| delivery_method | string | 否 | 平台下载、自动交付、人工发放等公开信息 |

| update_frequency | string | 否 | 一次性/月度/季度/年度/不确定 |
| customization | enum | 否 | `none/light/custom/unknown` |
| language | string | 否 | 主要语言 |
| copyright_basis | string | 否 | 原创/授权/公开许可/未知，不做无依据判断 |
| first_seen | date | 是 | 第一次发现日期 |
| last_seen | date | 是 | 最近核验日期 |
| product_status | enum | 是 | `active/inactive/unknown` |

### product 去重原则

- 同一主体同一核心交付物仅因标题改写，不新建 product。
- 同一产品在 Etsy、小红书、Gumroad 等不同平台分别建 listing。
- 产品发生重大交付结构变化时可升级版本，但保留原 product_id 与版本历史。

## 4. listing 表
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| listing_id | string | 是 | 平台上架记录稳定 ID，如 `lst_etsy_000001` |
| product_id | string | 是 | 关联逻辑产品 |
| platform | string | 是 | 小红书/Etsy/Gumroad/淘宝/闲鱼等 |
| listing_title | string | 是 | 页面原始标题 |
| listing_url | url | 是/优先 | 可复核 URL；不稳定时保存可定位搜索词 |
| platform_listing_id | string | 否 | 平台公开可见的商品/页面 ID |
| seller_name | string | 否 | 上架主体公开名称 |
| published_at | date | 否 | 页面可见发布日期；不可见则空 |
| currency | string | 否 | CNY/USD 等 |
| current_price | decimal | 否 | 当前公开价格；不可见则空 |
| original_price | decimal | 否 | 划线价/原价，仅在页面明确可见时记录 |
| pricing_model | enum | 否 | `one_time/subscription/bundle/pay_what_you_want/free/unknown` |
| sales_signal | string | 否 | 公开可见销量、已售、购买人数等原始信号 |
| rating | decimal | 否 | 公开评分 |
| review_count | integer | 否 | 公开评价数 |
| favorites_or_saves | integer | 否 | 公开收藏/喜欢数 |
| listing_status | enum | 是 | `active/inactive/deleted/unknown` |
| first_seen | date | 是 | 第一次发现 |
| last_seen | date | 是 | 最近核验 |
| source_level | enum | 是 | A/B/C/D/E 证据等级 |

### listing 校验

- `current_price` 仅存数值，币种放 `currency`。
- “销量 1k+”等模糊值不要伪造为精确 1000；原始文本放 `sales_signal`。
- 页面不可见的评价、销量、发布时间必须为空，而不是填 0。
- URL 去除不影响页面定位的追踪参数，保留稳定页面标识。

## 5. evidence_snapshot 表
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| evidence_id | string | 是 | 快照 ID |
| entity_type | enum | 是 | `competitor/product/listing/rule` |
| entity_id | string | 是 | 被观察实体 ID |
| source_type | string | 是 | 官方规则/商品页/笔记/评论/搜索结果/评价等 |
| source_url | url | 是/优先 | 可复核来源 |
| observed_at | datetime | 是 | 实际观察时间 |
| metric_name | string | 否 | likes/saves/comments/sales/reviews/rating 等 |
| metric_value | number | 否 | 仅当可精确读取时填写 |
| metric_raw | string | 否 | `1k+`、`100+ sold` 等原始显示文本 |
| evidence_level | enum | 是 | A官方/B交易/C内容/D用户表达/E推断 |
| evidence_summary | text | 是 | 对证据的简短客观转述 |
| confidence | enum | 是 | `high/medium/low` |
| valid_until | date | 否 | 有明确失效期时填写 |
| status | enum | 是 | `valid/stale/unverifiable/deleted` |

### 快照原则

动态指标不得只覆盖最新值。每次跨扫描周期发现重要变化时新增快照，以便计算：
- 7/30/90 天互动增长
- 价格变化
- 评价增长
- 商品上下架变化
- 竞品新增速度

| list_price | decimal | 否 | 原价/标价 |

## 7. review_insight 表

不要保存无必要的评论者身份信息；重点保存需求语义和可复核定位。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| insight_id | string | 是 | 洞察 ID |
| listing_id | string | 否 | 来源于商品评价时关联 listing |
| product_id | string | 是 | 关联逻辑产品 |
| source_url | url | 是/优先 | 评价/评论可定位来源 |
| observed_at | date | 是 | 采集日期 |
| signal_type | enum | 是 | `praise/complaint/request/question/purchase_intent/refund_reason` |
| theme | string | 是 | 价格/格式/内容完整性/更新/难度/交付/售后等 |
| user_need | text | 是 | 将用户原话归纳为需求，不写无依据画像 |
| short_excerpt | text | 否 | 必要的短摘录；避免大段复制 |
| desired_outcome | text | 否 | 用户想得到的结果 |
| desired_format | string | 否 | Excel/PDF/Notion/清单等 |
| severity | integer | 是 | 1–5；5 表示强痛点/强购买信号 |
| evidence_level | enum | 是 | 通常为 D；交易评价可同时作为 B/D 辅助证据 |
| notes | text | 否 | 抽样范围、上下文限制 |

### 洞察归类建议

统一使用有限主题词表，避免 Agent 每次发明新标签：
- `too_expensive` 价格高
- `too_complex` 太复杂/不会用
- `too_shallow` 内容太浅
- `missing_item` 缺关键资料
- `outdated` 内容过时
- `poor_format` 格式不好用
- `delivery_issue` 交付问题
- `needs_customization` 需要个性化
- `wants_template` 明确求模板/表格
- `wants_update` 需要持续更新

## 8. change_event 表
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| event_id | string | 是 | 变化事件 ID |
| detected_at | datetime | 是 | Agent 发现变化的时间 |
| entity_type | string | 是 | competitor/product/listing/lane/rule |
| entity_id | string | 否 | 对应实体；赛道级事件可为空 |
| change_type | enum | 是 | 见下方标准类型 |
| before_value | text/json | 否 | 变化前值 |
| after_value | text/json | 否 | 变化后值 |
| significance | enum | 是 | `low/medium/high` |
| source_url | url | 是/优先 | 可复核来源 |
| evidence_level | enum | 是 | A/B/C/D/E |
| agent_interpretation | text | 否 | 对商业意义的推断，必须与事实字段分开 |
| review_status | enum | 是 | `auto_ok/human_reviewed/needs_review` |

标准 `change_type`：
- `new_competitor`
- `new_product`
- `price_change`
- `sales_signal_change`
- `review_change`
- `new_format`
- `product_update`
- `listing_removed`
- `demand_spike`
- `demand_drop`
- `rule_change`
- `risk_change`
- `score_change`

只有跨越业务阈值或具有解释价值的变化才进入周报，避免每个小数值波动都触发通知。

## 9. 赛道聚合字段

为了给 100 分评分表提供输入，建议按 `lane_id + snapshot_date` 聚合：
- active_competitor_count
- active_listing_count
- recent_90d_note_count（仅在数据可获得时）
- high_save_signal_count
- request_material_signal_count
- paid_evidence_count
- median_visible_price
- price_min / price_max
- new_competitor_30d
- new_product_30d
- negative_review_theme_top3
- evidence_count
- evidence_diversity_count
- compliance_risk_level
## 10. 证据等级统一定义

| 等级 | 名称 | 可用于什么 | 不可用于什么 |
|---|---|---|---|
| A | 官方/规则 | 合规、类目、平台政策、官方定义 | 直接证明市场付费规模 |
| B | 交易证据 | 价格、公开销量、真实评价、在售状态 | 单独证明长期趋势 |
| C | 内容可见信号 | 点赞、收藏、评论、发布时间、内容频率 | 等同真实购买 |
| D | 用户表达 | 痛点、求资料、询价、差评、需求语言 | 外推总体市场规模 |
| E | 推断/假设 | 提出下一步验证问题 | 作为已证实事实 |

`evidence_diversity_count` 统计独立证据类型，而不是 URL 数量。
十个转载同一来源的页面不能算十个独立证据。

## 11. ID 规则

建议统一使用前缀 + 平台/日期 + 序号或短哈希：

```text
cmp_xhs_000001
prd_000001
lst_etsy_000001
ev_20260829_ab12cd
px_20260829_000001
ins_20260829_000001
chg_20260829_000001
```

ID 创建后不可因名称变化而修改。

## 12. 空值、0 与未知值

必须严格区分：
- `null/空`：未公开、无法获取或尚未核验
- `0`：来源明确显示为零
- `unknown`：枚举状态无法判断
- `unverifiable`：过去有记录，但当前无法重新验证

禁止把空值批量转换为 0，否则会严重扭曲市场判断。

## 13. 时间字段统一使用：
- 日期：`YYYY-MM-DD`
- 时间：ISO 8601，建议保留时区
- `first_seen`：数据库第一次发现，不等同平台发布时间
- `published_at`：只有页面明确可见时才填
- `last_seen`：最后一次确认实体仍存在/有效
- `observed_at`：动态指标实际采集时间

## 14. 金额字段

价格必须至少拆为：
- numeric value
- currency
- pricing model
- observed_at

不要把“¥19.9起”“$12 monthly”“买二送一”等混成一个无法计算的文本字段。
无法解析时保留 `price_note` 和页面原始信息，数值字段留空。

## 15. URL 标准化与去重

Agent 写入前：
1. 去掉常见追踪参数，但不得删除决定页面身份的参数。
2. 统一协议、主机名大小写等可安全归一化部分。
3. 优先使用平台稳定商品/笔记 ID 作为辅助键。
4. URL 相同但商品内容完全变化时记录 `product_update`，人工判断是否新建 product。
5. 搜索结果页不是商品永久 URL，只能作为辅助证据。

## 16. 数据更新策略

### 可覆盖字段
- normalized_name
- last_seen
- status
- 归一化标签

### 不应直接覆盖
- 历史价格
- 历史销量/互动/评价数
- 历史规则内容
- 已确认的变化事件

这些数据必须追加快照，保留时间序列。

## 17. Agent Upsert 逻辑
推荐顺序：

```text
normalize source
  -> resolve competitor
  -> resolve product
  -> resolve listing
  -> compare last snapshot
  -> append evidence/price snapshot
  -> create change_event when threshold crossed
  -> update last_seen/status
  -> trigger affected lane rescore
```

Upsert 前必须检查主键、URL、标准化名称和平台 ID，避免重复创建。

## 18. 变化判定建议

默认只在有意义时生成事件：
- 价格变化：绝对值或比例达到设定阈值
- 新竞品：首次发现且具有实际同类产品
- 新产品形态：交付形式此前未出现或明显改变竞争格局
- 评价/销量：跨越重要数量级或增长速度异常
- 内容需求：多个独立样本同时显示趋势，而非单篇爆款
- 规则：官方文字变化可能影响内容发布、经营、交付或导流

阈值应配置化，不写死在 Agent Prompt 中。

## 19. 数据质量门禁

竞品记录进入评分计算前至少满足：
- 有 `product_id`、赛道、用户任务
- 有可复核来源或明确可定位信息
- 有 `observed_at/last_seen`
- 动态指标注明观察时点
- 不可见数据未被伪造为 0
- 交易结论与内容热度结论没有混淆
- 推断字段没有覆盖事实字段

低质量数据可以保存，但必须标记 `confidence=low` 或 `status=unverifiable`，不得驱动高置信决策。

## 20. 合规与隐私字段限制
仅采集完成商业研究所必需的公开信息。

禁止字段/行为：
- 非公开手机号、地址、身份证件、账号凭据等个人敏感信息
- 推断创作者真实身份、家庭情况、健康情况等无关属性
- 绕过登录、验证码、付费墙获取数据
- 批量保存与研究无关的个人评论者资料
- 将侵权来源标成“可合法复用”而无授权依据

对版权只记录可确认的许可/原创声明；不确定时填 `unknown` 并进入风险复核。

## 21. 建议的最小 CSV/表格集合

若暂不使用数据库，可建立：

```text
data/competitors.csv
data/products.csv
data/listings.csv
data/evidence_snapshots.csv
data/price_snapshots.csv
data/review_insights.csv
data/change_events.csv
```

所有表统一包含 `created_at`、`updated_at`（适用时）和稳定 ID。

## 22. 与 100 分评分表的映射

- 痛点强度：review_insight 的 complaint/request/severity
- 小红书需求强度：小红书笔记及近期快照
- 收藏/保存意图：收藏、收藏/点赞比、清单型内容占比
- 求资料信号：评论需求样本
- 付费验证：listing + price + sales/review evidence
- 竞争友好度：active competitor/listing、新增速度、同质化
- 差异化空间：差评主题、missing_item、new_format、未满足需求
- 制作成本友好度：产品交付结构和内部制作估算
- 更新/复购潜力：update_frequency、规则/工具变化
- 合规友好度：Rule Agent 风险记录

评分 Agent 不得仅依据自己生成的文字摘要打分，必须回查底层记录。

## 23. v1.0 验收标准
数据库/表格实现至少应做到：
1. 同一产品跨平台不会被误判为多个逻辑产品。
2. 同一平台页面的价格和互动历史可追溯。
3. 所有关键商业结论能回到来源 URL 和观察时间。
4. 空值、零值、未知值严格区分。
5. Agent 能识别新增竞品、价格变化、新产品形态和下架。
6. 评价/评论洞察不依赖保存用户敏感身份信息。
7. 数据可直接映射到赛道 100 分评分模型。
8. E 级推断不能提升为 A–D 级事实。
9. 规则或版权高风险记录能触发人工复核。
10. 数据结构允许未来从 Excel/CSV 无损迁移到 SQLite/PostgreSQL。

## 24. 推荐唯一约束

实现数据库时建议至少设置：

```text
UNIQUE(platform, platform_account_id)       -- 有公开稳定账号ID时
UNIQUE(competitor_id, normalized_name)      -- 逻辑产品辅助去重
UNIQUE(platform, platform_listing_id)       -- 有稳定商品ID时
UNIQUE(listing_id, observed_at, metric_name) -- 指标快照防重复
UNIQUE(listing_id, observed_at)              -- 价格快照可按实现调整
```

如果平台 ID 缺失，不要强行用作者昵称作为永久唯一键，应使用内部 ID + URL/名称相似度进入待复核队列。

## 25. 核心原则

> 竞品库不是“商品收藏夹”，而是一个带时间、证据等级和变化历史的市场状态数据库。

只有这样，AI Agent 才能回答“最近新增了什么、什么在涨价、什么需求变强、哪个赛道从观察跨入 MVP”，而不是每轮重新搜索后给出互相矛盾的印象判断。
