# 虚拟资料赛道调研 SOP v1.0

- 版本：v1.0
- 目标：把虚拟资料赛道调研标准化为 AI Agent 可重复执行、可审计、可持续扫描的流程。
- 适用对象：PDF、Excel、Word、PPT、Notion、Prompt、工作流、图纸、清单、模板、教程包、项目包、资料库等 C 端数字资料。
- 核心原则：规则先行、证据驱动、多源交叉、保存原始信号、评分只做初筛、最终以真实支付验证为准。

## 1. 调研目标

每轮调研必须回答五个问题：
1. 用户正在完成什么复杂任务？
2. 用户在哪些节点容易犯错、焦虑、反复搜索或请求资料？
3. 是否存在强保存、强求资料、强付费信号？
4. 现有供给是否存在质量、格式、更新、细分人群或交付方式缺口？
5. 该机会是否满足平台规则、版权、类目和经营合规要求？

最终输出不是“热门内容列表”，而是可进入产品验证的候选赛道。

## 2. 标准产物

每轮扫描至少更新以下资产：
- `虚拟资料赛道100分评分表_v1.0.xlsx`
- `小红书笔记采集表_v1.0.xlsx`
- `竞品数据库字段规范_v1.0.md` 对应的竞品数据集
- 本轮调研简报：新增机会、变化、淘汰理由、规则风险、待验证问题

## 3. 赛道定义

赛道必须写成“人群 + 任务 + 阶段 + 资料形态/结果”，避免只写大类。例如：
- 差：装修资料
- 好：第一次装修的 80–120㎡毛坯房业主，在签合同到水电验收阶段使用的预算+验收项目包
- 差：AI 教程
- 好：非程序员用 7 天完成个人知识库 Agent 的项目式学习包

## 4. Agent 角色分工

建议拆为 5 个逻辑角色，可由一个 Agent 串行执行：

| 角色 | 职责 |
|---|---|
| Rule Agent | 学习平台规则、类目、版权、行业限制，维护风险清单 |
| Discovery Agent | 扩展关键词、发现新赛道和新内容信号 |
| Evidence Agent | 采集笔记、评论、竞品、价格、销量/评价等可复核证据 |
| Scoring Agent | 按 100 分模型评分、标记证据充分度和门禁结果 |
| Review Agent | 去重、发现冲突证据、检查过期数据并生成变化简报 |

任何角色不得把推断写成事实；所有结论必须能回溯到数据行或来源 URL。

## 5. 输入

最低输入：
- 目标市场：中国大陆 / 海外 / 两者
- 候选大类或允许 Agent 自行发现
- 时间窗口：默认近期 90 天，必要时补充历史趋势
- 预算/制作能力约束：可选
- 明确排除的高风险行业：可选
- 上一轮评分表、笔记表、竞品数据库（若存在）

## 6. 资料来源优先级按“规则证据 > 交易证据 > 内容信号 > 用户表达 > 推断”使用：

| 等级 | 证据类型 | 例子 | 用途 |
|---|---|---|---|
| A | 官方/平台规则 | 小红书官方规则、类目规则、版权/监管文件 | 判断能不能做 |
| B | 交易证据 | 店铺成交、销量、评价、价格、在售状态 | 判断是否付费 |
| C | 公开内容信号 | 笔记互动、搜索结果、发布时间、内容频率 | 判断需求热度 |
| D | 用户表达 | 评论“求模板/怎么买/哪里下载/踩坑”等 | 判断需求语言 |
| E | 推断 | Agent 基于多个信号形成的假设 | 仅用于提出待验证假设 |

至少两类独立证据支持的重要结论，才可标记为“已验证”；单一爆款只能算线索。

### 国内来源
- 小红书：核心需求发现与内容验证
- 抖音/B站：视频内容热度、教程型需求
- 知乎/贴吧/豆瓣/公众号/微博：复杂问题、长文本抱怨、经验复盘
- 淘宝/闲鱼/其他公开交易页面：价格、商品形态、评价、销量可见信号

### 海外来源
- Etsy：可下载模板、Planner、图纸、Printable 等成熟商品形态
- Gumroad：AI、Prompt、教程、工作流、知识产品
- Pinterest：视觉型需求、季节趋势、装修/婚礼/手工/育儿灵感
- YouTube/Reddit：教程需求、问题语言、用户抱怨
- Google Trends/搜索：趋势、季节性、关键词扩展

## 7. 合规“养号”：账号环境建立

禁止将“养号”理解为刷赞、批量互动、伪装素人、批量账号或机械行为。正确目标是建立真实、稳定、垂直的观察环境：
1. 正常注册并完善基本资料。
2. 围绕 2–3 个相关主题进行真实搜索和阅读。
3. 收藏真正有研究价值的内容，关注核心创作者/机构。
4. 仅在确有价值时自然点赞或评论，不执行固定次数脚本。
5. 不迷信“7天/14天养号”等未经官方确认的固定周期。
6. 研究账号与正式经营账号的数据用途应清晰区分。

Agent 不得执行模拟真人的刷量策略，不得以规避平台风控为目标设计自动化。

## 8. 小红书规则学习工作流

Rule Agent 每轮扫描前执行：
1. 检查社区公约、内容规则、专业号/商业营销规则是否有更新。
2. 检查目标赛道是否涉及教育、医疗、金融、法律、考试、招聘、版权等特殊约束。
3. 检查商品类目、主体、资质、虚拟商品交付、退款售后等要求。
4. 检查导流、私信、评论、主页联系方式等限制。
5. 记录规则 URL、发布日期/更新时间、核验日期、影响范围。
6. 与上一版规则快照比较，生成 `rule_change` 事件。

出现以下情况必须转人工复核：
- 规则互相冲突或无法判断适用范围
- 目标产品需要专业资质/许可
- 涉及第三方版权内容的大量复制、翻译、改编或再销售
- 产品交付方式可能涉及站外交易/违规导流
- 涉及医疗、金融、法律等高风险建议

## 9. 赛道发现优先发现具有以下特征的任务：
- 决策复杂：步骤多、选择多、信息依赖强
- 信息碎片化：需要阅读大量内容才能完成
- 犯错成本高：金钱、时间、机会或情绪损失明显
- 新手比例高：用户通常第一次经历
- 强保存：天然需要清单、表格、时间表、流程图、模板
- 强更新：政策、工具、价格、规则或阶段变化频繁

建议优先搜索“任务”而不是“资料”。

### 9.1 种子关键词结构

建立“问题词 × 场景词 × 结果词 × 资料词”：
- 问题词：踩坑、避雷、后悔、不会、怎么选、预算超支
- 场景词：第一次、孕周、入园、签合同、面试前、交房、买车前
- 结果词：清单、时间表、步骤、对比、预算、验收、计划
- 资料词：模板、Excel、PDF、表格、图纸、Prompt、工作流、项目包

### 9.2 关键词扩展

每个种子词至少扩展：
1. 搜索联想词
2. 标题高频词
3. 评论中用户原话
4. 竞品标题/商品标题中的长尾词
5. 海外对应英文关键词

输出格式：`keyword -> intent -> task_stage -> source -> first_seen -> last_seen`。

## 10. 小红书搜索与笔记采集每个候选细分赛道首轮建议采集 20–50 条代表笔记，并覆盖三类样本：
- Top 爆款：观察需求上限和传播表达
- 最近 30–90 天：观察当前趋势和新供给
- 中腰部账号：判断普通创作者是否也能获得需求响应

每条笔记写入 `小红书笔记采集表_v1.0.xlsx`，至少记录：
- 搜索关键词、标题、URL/可定位信息、发布日期（可见时）
- 作者/作者类型、可见互动数据
- 收藏/点赞比、求资料评论数、求资料率
- 用户任务阶段、内容类型、产品/交易信号、产品形态
- 证据等级、最近核验日期、状态、风险备注

不可见的数据必须留空，不允许根据经验补齐或估算。

## 11. 评论需求提取

评论是虚拟资料赛道的重要需求语料。优先识别：
- 求、蹲、发一下、求模板、求表格、求完整版
- 哪里下载、怎么下载、怎么买、多少钱
- 有 Excel/Notion/PDF/清单吗
- 看不懂、不会做、怕漏、求步骤、求对比
- 已买/买过/值不值/太复杂/缺少某功能

评论样本写入“评论需求样本”工作表，并标记信号类型和需求强度。

`求资料率 = 明确求资料评论数 / 可见评论数`，仅作为启发式信号。

Agent 必须注明抽样范围；不得把少量评论外推为总体市场规模。

## 12. 保存意图判断重点观察：
- 收藏显著高于同类笔记
- 收藏/点赞比较高
- 评论出现“先收藏”“以后照着做”
- 内容本身是清单、流程、预算、时间表、对比表

`收藏/点赞比 = 收藏 / 点赞` 仅用于同赛道横向比较，不是平台官方算法指标。

## 13. 竞品研究

每个候选赛道至少记录 10 个有效竞品/商品，优先覆盖：
- 国内免费内容替代品
- 国内收费数字产品
- 海外成熟数字产品
- 新上架/快速增长产品
- 高评分与高差评产品

研究字段按 `竞品数据库字段规范_v1.0.md` 执行。

重点回答：
1. 用户为什么买？
2. 交付物是什么，而不是营销标题是什么？
3. 价格带和定价模型是什么？
4. 用户差评和未满足需求是什么？
5. 是否存在格式、细分人群、自动化、更新频率、体验上的缺口？
6. 竞品是否依赖侵权内容、违规导流或不可复制资源？

## 14. 跨平台付费验证

小红书证明“有人关注/想要”，交易平台用于证明“有人付款”。

同一需求至少尝试在 2 个独立渠道寻找付费或成交证据，例如：
- 小红书公开商品/交易信号 + 淘宝/闲鱼
- 小红书 + Etsy
- 小红书 + Gumroad
- 国内内容信号 + 海外成熟产品评价

若只有内容热度、没有任何付费证据，付费验证不得评 4–5 分。## 15. 产品机会抽象

把“内容主题”转换成“任务系统”：

`用户 + 场景 + 任务阶段 + 决策节点 + 交付物 + 结果`

例如不要输出“装修资料”，而应拆成：
- 装修总预算 Excel
- 签约前合同核对清单
- 水电节点验收表
- 主材采购进度表
- 增项变更记录表
- 完工验收清单

优先考虑“清单 + 决策 + 流程 + 模板 + 验证工具”的组合包，而不是单个换皮文件。

## 16. 100 分评分

统一使用 `虚拟资料赛道100分评分表_v1.0.xlsx`：

| 指标 | 权重 |
|---|---:|
| 用户痛点强度 | 15 |
| 小红书需求强度 | 15 |
| 收藏/保存意图 | 10 |
| 求资料信号 | 15 |
| 付费验证 | 15 |
| 竞争友好度 | 10 |
| 差异化空间 | 8 |
| 制作成本友好度 | 4 |
| 更新/复购潜力 | 3 |
| 合规友好度 | 5 |
| 合计 | 100 |

每项采用 1–5 分锚点，5 分始终代表“更适合进入”。
“竞争、制作成本、合规”使用友好度表达，避免反向计算错误。

另外单独填写“证据充分度 1–5”，不计入总分，但参与门禁。## 17. 自动门禁

默认参数：
- 总分 ≥ 75 且证据充分度 ≥ 3：`进入MVP`
- 总分 60–74.9 且证据充分度 ≥ 3：`继续观察`
- 总分 < 60：`淘汰/搁置`
- 证据充分度 < 3：无论总分多少均为 `证据不足`

门禁只代表是否值得投入下一步验证，不代表“必然赚钱”。

以下情况即使高分也必须人工复核：
- 合规友好度 ≤ 2
- 主要价值来自搬运、盗版、无授权翻译/整理
- 交易证据无法复核或疑似刷量
- 价格/销量结论仅来自单个平台单个商品
- 主要需求来自短期热点且没有持续性证据

## 18. 持续扫描工作流

### 日常/每次运行
1. 读取上一轮数据库和 `last_seen`。
2. 检查规则更新和重大平台变化。
3. 对 Top 赛道执行近期关键词搜索。
4. 采集新笔记、新评论需求样本、新竞品。
5. 对已有 URL/商品执行状态与互动快照更新。
6. 去重并写入新增证据。
7. 重算受影响赛道评分。
8. 仅报告“实质变化”，避免重复旧信息。

### 每周
- 扫描 3–5 个新候选大类或新长尾关键词
- 汇总新增赛道、升分/降分赛道、新竞品、新价格带
- 输出 Top 10 机会池和 Top 3 深挖建议
- 清理失效 URL、重复记录和无法复核的数据

### 每月
- 全量复核平台规则
- 重估权重和门禁是否需要调整
- 复盘已经做过 MVP 的赛道：预测评分 vs 实际支付结果## 19. 去重与更新

### 笔记
- 第一优先键：标准化 URL
- 无稳定 URL：平台 + 标准化标题 + 发布日期 + 作者/可定位信息
- 同一笔记多次抓取不得重复创建主记录，应产生新的互动快照或更新 `last_seen`

### 竞品
- `product_id` 对应逻辑产品
- `listing_id` 对应具体平台上架页面
- 同一产品在不同平台分别建 listing，避免价格和销量信号互相覆盖

### 证据
- 保存 `observed_at`，禁止只保留“当前值”
- 价格、销量、评价数等变化数据建议追加快照
- 页面删除时状态改为 `失效/删除`，不要删除历史证据

## 20. 数据质量规则

Agent 写入前必须检查：
- URL 是否可定位、是否重复
- 日期格式是否统一为 `YYYY-MM-DD`
- 金额是否同时记录数值和币种
- 不可见数据是否保持空值，而非 0
- “0”只表示明确可见为零
- 评分是否有对应证据
- 证据是否仍在有效时间窗口
- 推断是否显式标记为 E 级或“待验证”

禁止伪造互动、销量、评价、发布日期、搜索量或用户画像。

## 21. 变化事件

持续扫描时生成以下 `change_type`：
- `new_competitor`：出现新竞品
- `price_change`：价格明显调整
- `demand_spike`：近期需求信号明显上升
- `demand_drop`：近期信号下降
- `new_format`：出现新产品形式/交付方式
- `rule_change`：平台规则或类目发生变化
- `risk_change`：版权/资质/导流风险变化
- `score_change`：总分跨越门禁阈值

变化必须附带 before/after、核验日期和证据 URL。## 22. AI Agent 输出契约

每次运行最终输出必须包含：
1. `run_id`、扫描时间、时间窗口、平台范围
2. 新增候选赛道
3. 升分/降分赛道及原因
4. 新增高价值笔记和评论需求信号
5. 新竞品、价格或产品形态变化
6. 规则/版权/经营风险变化
7. Top 10 评分表摘要
8. Top 3 下一步验证动作
9. 证据不足项和未知项

不得只输出结论而省略来源。

### Top 3 下一步动作模板

每个 Top 3 必须给出：
- 最小目标用户
- 最小任务边界
- MVP 交付物
- 建议价格验证区间
- 3–10 个内容测试主题
- 需要补充的关键证据
- 最大失败风险
- 继续/停止的可观察判据

## 23. 内容 MVP

进入 MVP 前先做低成本内容验证：
- 发布/设计 3–10 个围绕具体任务节点的原创内容测试
- 优先测试收藏、求模板、询价、问题深度，而不是只看点赞
- 不以虚构案例、批量 AI 洗稿、诱导互动制造假需求
- 不承诺无法证明的效果

内容验证通过后，再制作最小可付费产品。

## 24. 支付验证支付验证优先于继续扩充资料量：
1. 从最核心任务制作可交付 MVP。
2. 价格可从低客单测试，但不能用“免费领取量”替代付费需求。
3. 记录访问/询问/购买/退款/售后问题。
4. 将真实结果回写评分体系，特别是“付费验证”和“差异化空间”。
5. 若用户购买后仍需要大量人工解释，评估是否应升级为产品化服务而非资料包。

## 25. 停止条件

满足任一条件应停止继续投入或降级为观察：
- 连续两轮评分 < 60
- 无法找到可复核付费证据
- 用户只要免费资源且无明显付费意愿
- 主要优势只能靠盗版/搬运/侵权实现
- 平台规则明确禁止或资质成本不合理
- MVP 有流量但持续无支付
- 售后/更新成本明显超过客单价承受范围

## 26. 安全与红线

Agent 不得：
- 执行刷量、批量养号、虚假互动、虚假评价
- 绕过登录、验证码、付费墙或平台访问控制
- 收集不必要的个人敏感信息
- 把第三方受版权保护内容原样打包出售
- 自动发送营销私信或诱导站外交易
- 把医疗、金融、法律等高风险资料包装成专业结论替代品
- 用单一爆款、单一评论或单一商品销量代表市场规模

## 29. v1.0 验收标准

一套可被 Agent 自动运行的调研结果至少满足：
1. 每个进入 MVP 的赛道 ≥10 条有效证据，且至少覆盖 2 类独立证据。
2. 每个重点赛道有近期小红书样本，而不是只依赖历史爆款。
3. 付费验证评分 ≥4 的赛道必须存在可复核交易/评价/价格证据。
4. 所有高风险规则判断保留官方来源与核验日期。
5. 数据可去重、可增量更新、可发现价格/热度/规则变化。
6. 评分表可自动给出 MVP/观察/淘汰/证据不足状态。
7. Agent 明确区分事实、用户表达和推断。
8. 最终 Top 3 都有具体的下一步 MVP 和支付验证计划。

## 30. 核心判断原则

> 不要寻找“什么 PDF 好卖”，要寻找“用户正在完成什么复杂任务”。

优质机会通常是：

**高掉坑风险 × 高保存需求 × 高求资料信号 × 已有付费证据 × 供给缺口 × 合规可经营。**

本 SOP 后续应根据真实 MVP 转化、退款、复购结果持续校准评分权重，而不是长期把内容互动当作最终答案。
