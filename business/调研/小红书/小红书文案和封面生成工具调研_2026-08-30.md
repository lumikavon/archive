# 小红书文案与封面生成 Skill / MCP / 工具调研

> 调研日期：2026-08-30  
> 目标：为“小红书文案 + 封面/图文卡片生成 Skill”选型，重点参考 GitHub、X、小红书公开页面及产品官网。  
> 适用定位：AI Agent 与效率内容约 70%，求职/招聘/职场内容约 30%。

## 一、结论先行

1. **文案、视觉和发布应拆成三个模块。** 当前热门项目大多只在其中一到两个环节突出；把所有能力绑进一个不可检查的“全自动爆款工具”，会同时放大事实错误、视觉失真和账号风控。
2. **封面/图文首选两条路线并存：**
   - 可控排版路线：`guizang-social-card-skill`、`Auto-Redbook-Skills`，用 HTML/模板渲染，中文文字、截图和品牌一致性更稳定。
   - AI 原生视觉路线：`baoyu-xhs-images`、`xhs-visual-director-skill`、`RedInk`、`AI Canvas`，创意更强，但必须检查中文文字、人物/产品真实性和界面截图。
3. **数据调研与发布能力首选 `xpzouying/xiaohongshu-mcp` 作为参考底座**，但建议先只启用搜索、读取和草稿辅助；发布、评论、点赞等外部动作默认要求人工确认。
4. **针对当前赛道，推荐“半自动内容工厂”而非无人值守矩阵：** 公开资料取证 → 标题/正文草稿 → 真实截图或可核验素材 → 封面/卡片 → 人工事实与合规检查 → 手工发布或确认后发布。
5. **最值得借鉴的组合：** `Lingzao/xhs-content` 的调研结构 + 自建文案规则 + `Guizang` 的确定性排版 + `Baoyu/ImageGen` 的原创视觉 + MCP 的只读检索。不要直接拼接许可证不兼容的代码。

## 二、调研口径与局限

- GitHub 热度使用 2026-08-30 仓库页面可见 Star，数字会继续变化；Star 代表关注度，不等于生产可用性。
- X 用于发现近期传播和真实使用讨论，不把单条宣传帖当作效果证明。
- 小红书普通笔记在公开搜索引擎中的索引不稳定，本报告未虚构点赞、收藏或评论数据；小红书侧主要采用官方 REDSkill 页面与公开协议作平台级信号。
- “爆款”“提升点击率”“安全不封号”等表述若仅来自作者宣传，均视为待验证，不作为事实结论。
- 自动搜索、抓取、点赞、评论、发布可能触发平台风控或违反平台规则；应使用本人账号、低频操作、最小权限和明确的人审闸门。

## 七、面向当前赛道的选型建议

### 方案 A：安全、可控的半自动工作流（推荐）

| 环节 | 推荐组件 | 关键控制 |
|---|---|---|
| 选题与证据 | `xiaohongshu-mcp` 只读能力 + Web/GitHub 官方资料 | 每条事实保留 URL、日期、可见互动与“待验证”标记；限制请求频率 |
| 文案 | 自建 `xhs-copy-cover-studio` Skill，吸收 Lingzao / xhs-content 的结构 | 不承诺“爆款”；5 个标题候选；事实、观点、体验分栏；保留个人语气 |
| 封面短文案 | PONYO 的视觉锚点检查 + 自建标题压缩规则 | 手机缩略图可读；不使用无法证明的“第一、唯一、必涨”等绝对化表达 |
| 图文卡片 | Guizang/HTML 渲染为主，Baoyu/ImageGen 为辅 | AI Agent 内容优先使用真实界面截图；AI 生成图不得伪装成真实产品界面 |
| 视觉迭代 | AI Canvas 或普通图片编辑器 | 保留 V1/V2；检查中文、截图、人物手部、Logo、品牌色和版权来源 |
| 发布 | 人工发布，或 MCP 到“待确认”状态后停止 | 默认不自动评论、点赞、收藏、群发或多账号批量操作 |
| 复盘 | 记录曝光、点击、停留、收藏、评论、关注、私信/成交 | 前 30 天只形成基线，不用少量样本下“爆款规律”结论 |

### 方案 B：追求速度的一站式工作流

- 使用 RedInk 生成大纲、文案和整套视觉；再用 Reditor/Canva 做事实校对、中文文字修复与品牌化。
- 优点是 7–14 天内能快速验证栏目形式；缺点是容易产生同质化、AI 味、虚构界面和不稳定的中文排版。
- 适合试验，不建议直接把自动生成稿批量公开发布。

### 方案 C：全自动运营

- 典型组合是 Auto-Redbook-Skills / xiaohongshu-ops + xiaohongshu-mcp。
- 仅建议在隔离测试账号、低频、人工确认、清晰日志和可立即停机的条件下试验。
- 不建议把自动点赞、自动评论、多账号互动作为首期能力；这类动作对内容验证价值低，却显著增加平台与声誉风险。

## 八、拟建 Skill 应吸收的能力与差异化

建议 Skill 名：`xhs-copy-cover-studio`

| 模块 | 必备能力 | 与现有工具的差异化 |
|---|---|---|
| Brief | 账号定位、目标人群、内容目标、证据材料、CTA、视觉资产 | 默认继承“AI Agent/效率 70% + 求职职场 30%”，但允许单篇覆盖 |
| 研究 | 搜索词、对标内容、来源包、事实核验、未知项 | 不把未核验互动、价格、功能和案例写成事实 |

| 封面 | 3 套封面方向、封面短标题、视觉锚点、配色/字体/布局 | 同时支持“确定性 HTML 卡片”和“ImageGen 原生视觉”两条路 |
| 图组 | 6–8 页递进结构、每页单一任务、末页 CTA | AI 工具类优先真实截图、流程图、对比表；职场类优先清单与情境卡 |
| 人审闸门 | 事实、版权、隐私、夸大宣传、未成年人、招聘歧视、劳动法表述 | 检查通过前不得自动发布；高风险内容要求来源和免责声明 |
| 交付 | `brief.md`、`sources.md`、`copy.md`、`cover-spec.md`、`cards/`、`qa.md` | 可追溯、可复盘、可重新生成，避免只返回聊天文本 |
| 复盘 | 版本、发布时间、数据窗口、表现指标、学习结论、下轮假设 | 区分观察与因果，不因一篇笔记就固化规则 |
